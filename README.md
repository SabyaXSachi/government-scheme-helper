# Government Scheme Helper

A RAG-based question answering system with a supervised category classifier and a
user-feedback learning loop. Machine Learning course project, 5th semester.

A user describes their situation in everyday words ("I need money for my college
fees") and the app answers from official government scheme text, with the source
shown, an information-only note, and thumbs up / thumbs down feedback that makes
the classifier better over time.

## How the ML fits together

| Stage | What happens | Where |
|---|---|---|
| 1. Train category model (offline) | TF-IDF features -> KNN and decision tree tuned on a validation set, 5-fold CV, overfitting curves, final test of both, deploy the winner | `src/classifier.py` |
| 2. Prepare scheme data (offline) | Scheme text -> chunks (200-400 words, small overlap) -> embeddings -> vector store | `src/build_vector_store.py` |
| 3. Answer a question (online) | Predict category -> vector search only within that category -> top 3 chunks -> grounded answer | `src/rag.py` |
| 4. Feedback loop | Thumbs up/down become labelled examples; every ~50 examples the model is retrained and replaces the old one only if the locked-test score is not worse | `src/feedback.py` |

Datasets (`data/`, generated by `data/generate_datasets.py`):

- **schemes.csv** — 48 schemes, 12 per category (Farmer, Student, Woman and Child,
  Senior Citizen), with eligibility, benefits, how-to-apply, documents and
  official source URL.
- **flashcards.csv** — 200 labelled user sentences, 50 per category.
- **evaluation_set.csv** — 50 locked evaluation questions with the known correct
  scheme and category. Never used for training or tuning.

## Quick start

```bash
pip install -r requirements.txt

python data/generate_datasets.py      # build the three datasets
python -m src.train_classifier        # stage 1: train + evaluate classifier
python -m src.build_vector_store      # stage 2: chunk, embed, store
python -m src.experiments             # retrieval experiment (baseline vs filtered)
python -m src.app                     # start the web app
```

Then open http://127.0.0.1:8000 (or run `run_app.bat` on Windows).

On first start the app builds any missing artefacts itself, so the two build
commands are only needed when you want the reports without starting the server.

## Outputs

- `reports/classifier_report.json` — split sizes, tuning grids, 5-fold CV, test
  comparison of KNN vs decision tree, per-class precision/recall/F1, confusion matrix.
- `reports/overfitting_curves.png` — train vs validation accuracy against K and
  against tree depth.
- `reports/confusion_matrix.png` — the deployed model on the locked test set.
- `reports/retrieval_experiment.json` + `.png` — baseline RAG vs
  category-filtered RAG, top-3 hit rate per category and overall.
- `storage/progress.json` — retraining rounds (accuracy after each round drives
  the progress page).
- `models/versions/` — every model version, kept.

## Configuration (all optional)

- **Embeddings**: the store is built with Sentence-BERT MiniLM
  (`all-MiniLM-L6-v2`) when sentence-transformers is installed; otherwise a
  TF-IDF embedding fallback keeps everything runnable offline. If the model
  download from Hugging Face stalls, set `HF_ENDPOINT=https://hf-mirror.com`
  before running `python -m src.build_vector_store`.
  Force a backend with `EMBEDDING_BACKEND=st|fastembed|tfidf`.
- **Answer generation**: set `OPENAI_API_KEY` (and optionally `OPENAI_BASE_URL`,
  `OPENAI_MODEL`) to have an LLM write the answer strictly from the retrieved
  chunks. The default is an extractive generator that assembles the answer from
  the retrieved scheme fields — it uses only retrieved text by construction.

## Honest notes

- The scheme corpus is a development seed compiled from public knowledge. Every
  record carries a `last_verified` date and must be re-checked against the
  official page before serious use (the project document requires this).
- The vector store does exact cosine search (what FAISS `IndexFlatIP` on
  normalised vectors returns) over a few hundred chunks; the FAISS/Chroma swap
  only matters at much larger scale.
- The app gives information only and does not confirm legal eligibility.
- If datasets are regenerated, retrain from scratch — the locked test split is
  deterministic only while `flashcards.csv` stays unchanged.
